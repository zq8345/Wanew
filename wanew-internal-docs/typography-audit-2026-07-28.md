## 1. 方法与其自证（先证明判据有效，再谈结论）

### ① 量的是渲染计算样式，不是 CSS 源码
全部数值取自浏览器 `getComputedStyle()`。**本次审计的头号发现（D1）正是源码与渲染不一致的案例**：`.footer-widget__title` 在 CSS 里写着 13px，在 /about/ 上实际渲染 17px。只读源码看不出来。

### ② 取证前先断言材料有效（拦下了一次假 P0）
每次测量前置硬闸：`--w3-bg` 计算值必须 == `#0a0c0f`，否则**拒绝出数**。

**实战记录**：首次抓 `/guides/` 时，全部角色读到 16px/w400/lh `NaN`/`rgb(0,0,238)`（浏览器默认样式），`--w3-bg` 为空。
若直接采信，会得出"**/guides/ 生产页无样式**"这一 P0 级结论。逐步证伪：

| 假设 | 检验 | 结果 |
|---|---|---|
| CSS 404 / MIME 错 | fetch 该 URL | 200，`text/css; charset=utf-8`，116535 bytes |
| Service Worker 返回 opaque 响应 | `getRegistrations()` / `controller` | 无 SW、无 controller → **证伪** |
| CSS 引擎坏 | 注入 `<style>` 探针 | 生效（37px）→ **证伪** |
| 文件内容不对 | 手动 fetch 同文件并注入 | 页面立即恢复（卡片 `#1e242e`/flex、h1 48px）→ **证伪** |
| 该次 `<link>` 加载失败 | PerformanceResourceTiming | 该条 `decodedBodySize=0`、`nextHopProtocol=""` → **成立** |
| 是否可复现 | 重载 | CSS 正常应用（decoded 125351 / h2）→ **瞬态确认** |

**结论：浏览器一次性加载失败，非生产缺陷，不予上报。**

### ③ 判据先自证
统计前先在**已知不一致**的样本上验证判据能报出来：注入两个同角色不同字号的 `h3`（19px / 17px）→ 判据报 **集合大小 = 2**（PASS）；再注入两个同值 `h3` → 报 **集合大小 = 1**（无误报）。
判据具备"报得出已知问题"的能力后，后面出现的"集合大小 = 1"才有信息量。

## 3. 逐条判定：刻意的差异 vs 漂移

> 排序**按影响面**（模板数 / 页数），不按严重度。
> 判据：宪法明文写了 = 刻意；宪法未写且同角色同上下文取值不一 = 漂移；判不准 = **存疑**（交总工，不猜）。

### 🔴 D1 — 共享页脚标题被 About 的页面级规则劫持
**影响：1 模板 / 4 页，但污染的是全站共享 chrome**

- 实测：`/about/` 的 `.footer-widget__title` = **17px/w650/ls1.36**；其它全部模板 = **13px/w600/ls1.04**。
- 根因（`el.matches()` 逐规则回溯，非推测）：

  | 命中该元素且设了 font-size 的规则 | 特异性 | 值 |
  |---|---|---|
  | `.footer-widget__title` | 0,1,0 | 13px / w600 / 0.08em |
  | **`.about-page h3`** | **0,1,1** | **17px / w650** ← 生效 |

- 判定：**漂移（确定）**。页脚是 `_chrome.html` 单源共享组件，不应因所在页面而变形。
- **这是根不是症**：模式 = *页面级后代元素选择器（`.page h3`）压过组件类选择器（`.component__title`）*。与总工今天实测的 `.xlc-section h3`(0,1,1) 压 `.about-qp-head`(0,1,0) **同一根**。
- 系统性复扫（本页全部 `.xxx h1|h2|h3|p|li` 规则 × 全部元素）：**当前只此 1 处造成真实字号改变**；`.about-page p`、`.xlc-body p` 等也命中共享元素，但只改行高/色、未改字号 → 良性，不报。
- 建议（修根）：禁止页面作用域使用裸元素后代选择器；或给共享 chrome 的选择器提升到同等特异性；或加一条守卫检查"chrome 组件的计算字号跨页是否恒定"。

### 🟠 D2 — `--w3-text3` 落在抬起表面上，对比度跌破 WCAG AA
**影响：≥54 页（列表 50 + contact 4），单页最多 33 处**

| 位置 | 色 | 背景 | 实测对比度 | 判定 |
|---|---|---|---|---|
| `.blog-one__tt`（列表卡元信息） | `#75808a` | 卡片 `#1e242e` | **4.42** | ⛔ < AA 4.5 |
| `label`（contact 表单标签） | `#75808a` | 面板 | **4.42** | ⛔ < AA 4.5 |
| 同色落**页面底** `#0a0c0f` | `#75808a` | `#0a0c0f` | 4.94 | ✅ 过 AA |

- 根因单一：`--w3-text3` 是按**页面底**校准的；一旦放到 `--w3-surface-2`（§2.6 卡片抬亮到 `#1e242e`）上，对比度被抬高的底色吃掉 0.5，跌破 4.5。
- 判定：**缺陷（客观标准，非风格偏好）**。表单标签尤其影响可用性。
- 建议（修根，二选一）：① 提亮 `--w3-text3`，或 ② 增设 `--w3-text3-on-surface` 并规定"卡片/面板内不得用 text3"。**不要逐处打补丁**。

## 4. 额外三件

### 4.1 字阶是否成体系 → **不完全成体系，且根因在宪法自身**

1440px 实测出现的字号（去重）：
`65.6 · 49 · 48 · 38.4 · 35.2 · 32 · 30 · 28.8 · 27.4 · 27.2 · 24 · 22 · 21 · 19 · 18 · 17.5 · 17 · 16.5 · 16 · 15.5 · 15 · 14.5 · 14 · 13.5 · 13 · 12.5 · 12 · 11.5 · 11` = **29 个**

- 大号段（≥22）比例关系尚可（65.6/49≈1.34、49/30≈1.63…），但混入 35.2 / 28.8 / 27.2 三个非阶梯值。
- **UI 段（11–16.5）是 0.5px 等差斜坡，不是比例刻度**：16.5 / 16 / 15.5 / 15 / 14.5 / 14 / 13.5 / 13 / 12.5 / 12 / 11.5 / 11 —— 相邻档差 3%–4%，**人眼分不出，但会让"同角色两个值"看起来像漂移**。
- **关键结构性观察**：这不是实现走样，是 **§2.2 宪法本身把档位写成了"带宽"**——`body 15–16`、`ui 14–14.5`、`ui-sm 13–13.5`、`caption 12–12.5`、`micro 11–11.5`。**按构造每个带就允许两个值**，所以在这些带里"集合大小=2"不能自动判为漂移。想要"一致性"可判定，宪法得先从带宽收敛成单值。
