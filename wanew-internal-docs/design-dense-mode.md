## 0. 判断标准（先说结论，免得又变成品味之争）

**好看 = 界面的视觉结构和信息的真实结构一致。** 一眼看得出哪些是同一类、哪些是主从、哪些可以忽略。
**丑通常不是缺装饰，是缺秩序。**

⇒ 下面每一条都可测。**不许用"感觉更好了"验收。**

---

## 1. 明度台阶（这条是主因，先做）

暗色界面的沉闷，根源是**底、面板、内容三者亮度几乎一样**，眼睛找不到从哪看起。
🔴 **靠明度分层，不靠描边。到处画 1px 边框是廉价感的头号来源。**

```
L0  页面底      #0B0C0E
L1  面板/卡片   #121417
L2  行/输入框   #191C20
L3  hover/选中  #21252B
发丝线（仅必要处：表头下沿、面板外沿）#262A30，1px
```
**规则**：相邻两级必须肉眼可辨。**默认无边框**；只有当两个同级面板相邻、不画线就分不出时才画。

## 2. 文字与对比

```
主要文字  #E7EAEE   （不用纯白 —— 纯白在暗底上会"振"）
次要文字  #9BA3AE
三级文字  #6B7280   仅用于标签/占位，不承载信息
```
**判据**：主要文字对 L1 ≥ 12:1；次要 ≥ 5:1；三级 ≥ 3:1 且**不得单独承载任何必要信息**。

## 3. 颜色：一个强调色 + 四个语义色

```
强调色（只此一个）= 品牌蓝
  用于：左栏选中项 · 主操作按钮 · 焦点环
  🔴 不用于：状态标签、表格内链接、次要按钮
语义色（只此四个，且都不做实心底）
  在线/正常  #3F9E63      草稿/待办  #B4863B
  下架/错误  #C15B58      中性       = 次要文字色
```
🔴 **状态用「6px 圆点 + 文字」，不用实心胶囊。**
> 每一行都挂一个彩色实心胶囊 = 全屏都在强调 = 等于没有强调。
> 现在后台里蓝色胶囊到处都是，所以蓝色已经不意味着任何东西。

**判据**：任意一屏内，强调色出现 ≤ 3 次。

## 4. 间距音阶

```
2 / 4 / 8 / 12 / 16 / 24 / 32 / 48    —— 只允许这些值
表格单元格   纵 8 / 横 12
行高         44px（单行）· 56px（带缩略图）   ← 这两个是【格子内容高】，见下方 ⚠️
面板内边距   16
区块间距     24
```
🔴 **留白不能均匀**：表格行内要紧，区块之间要松。**均匀的留白就是"沉闷"的技术定义。**
**判据**：扫一遍 CSS，不在音阶上的间距值 = 0。

⚠️ **「56px（带缩略图）」是 40 + 8 + 8 = 格子内容高，没有算行与行之间那条 1px 发丝线。**
```
格子内容高   40（缩略图）+ 8 + 8            = 56px
节距         格子内容高 + 1（分隔线）        = 57px   ← 决定"一屏塞得下几行"的是这个
```
> **判据一律用节距。** 2026-07-31 admin 实测：按「行距 ≤ 56」写判据，缩略图取任何值都到不了 ——
> 因为可取的最小节距就是 57。判据够不到，不是实现不达标，是那个数字量的是另一层。

🔴 **一个数字判据必须连着"量的是什么"一起写，否则它只是个数字。**
同一周内这件事发生了两次：一次是「可见」没定义（露出一半算不算），一次就是这里的「行距」量到哪一层。
**两次都不是谁量错了 —— 是两种量法都说得通，于是各人量各人的。**

⚠️ 另记一条 admin 侧量出来的结构，改缩略图尺寸前先看它：
```
节距 = max(缩略图, 标题两行截断高 40) + 8 + 8 + 1
```
所以缩略图小于 40px 时**一行都换不回**（撞到标题的底），大于 40px 时**每一像素都直接吃行数**。
**⇒ 任何"只有 X 决定 Y"的断言必须扫过区间才成立；在一个点上量出来的是那个点的形状。**

## 5. 字阶：三档字号，字重担层级

```
20 / 600   页面标题
15 / 600   区块标题
13 / 400   正文与表格（行高 20）
11 / 500   全大写标签，letter-spacing .06em，三级色
字重只用 400 / 500 / 600 —— 工具界面不用 700
```
**判据**：字号种类 ≤ 4。**六档字号 = 没有层级。**

## 6. 数字

```
font-variant-numeric: tabular-nums;   右对齐
```
**理由**：不等宽的数字会让列左右跳动，眼睛没法竖着扫。**这一条在数据后台里的收益大得不成比例。**

## 7. 表格

```
表头     11px 全大写三级色，无底色，下沿 1px 发丝线
行       无斑马纹；行间 1px 发丝线
标题列   固定 2 行截断（-webkit-line-clamp: 2），🔴 永远不许铺到 3 行
列宽     按【扫视频率】分配：状态/ID 窄且定宽 · 标题弹性 · 操作定宽靠右
操作     默认三级色文字按钮；行 hover 时才升到主要色
```
**判据**：1440×900 下可见产品行 ≥ 12 行（现状约 6 行）。

## 8. 交互

```
行 hover   背景升到 L3，100ms
焦点环     2px 强调色 40% 透明，offset 2px（键盘可见）
动效       工具界面里任何过渡 ≤ 150ms
```

## 9. 对齐

**整页要有一条贯穿的垂直基线**：左栏内容、主区标题、表格第一列左边缘对齐同一条线。
> 大部分"说不出哪里怪"的界面，怪在这里。

## 10. 验收（七条，全部可测；不许用观感代替）

```
① 1440×900 完整可见行数 ≥ 12   ← 完整可见 = rect.bottom ≤ innerHeight 且 rect.top ≥ 0
② 一屏内强调色出现 ≤ 3 次
③ 不在间距音阶上的值 = 0
④ 字号种类 ≤ 4
⑤ 主要文字对比 ≥ 12:1 · 次要 ≥ 5:1
⑥ 标题列 0 处超过 2 行
⑦ 数字列 100% 右对齐且 tabular-nums
```
🔴 **验收必须过生产快照关**：干净的种子数据只验逻辑；**真实数据（量大、值脏、有超长标题、有重复）才决定观感。**
⚠️ 行内元素不许随数据量膨胀 —— 长标题必须被截断规则吃掉，而不是把行撑高。

### 怎么读这些数（2026-07-31 补，都是被咬出来的）

⚠️ **① 的「可见」必须写成上面那行代码，不能只写"可见"。**
同一份页面，"露出一部分就算"读出 12 行，"整行都在视口内"读出 11 行。**两个人都没量错。**
定义没写下来的时候，**一个不合格的读数会自动挑一个让它合格的读法** —— 那不是不诚实，是判据留了口子。

🔴 **余量要报两个数，别只报一个，更别用形容词代替。**
```
贴边余量   = 视口高 − 表格上方 − 完整可见行数 × 节距     ← 最后那行离底边多远
判据余量   = 视口高 − 判据行数(12) × 节距 − 表格上方     ← 还能长多少才跌破判据
```
实测过一次「13 行 / 贴边余量 1.5px / 判据余量 58.5px」：**前一个数听着吓人，后一个才是要看的。**
反过来也发生过：「12 行 / 余量 3px」当时被写成"脆弱"就放过去了，而它按严格定义**已经越界**。
> **一个数字要么能触发动作，要么就别报。** "脆弱"拦不住下一个人加一段说明文字，58.5px 能。

⚠️ **量之前先断言材料有效。** 未排完版的那一帧会给出"缩略图 0px / 少一行"这种**全错但自洽**的读数，
它和真读数长得一模一样。至少断言：视口尺寸对、数据条数够、缩略图渲染尺寸 ≠ 0。

⚠️ **两个主题都要量。** 版式判据总是在某一个主题下量的 —— 另一个主题不合格，量的人根本不会知道。
（2026-07-31 admin：`width:44px` 只写在浅色里，于是深色 13 行、浅色 12 行，两边各自量各自的都看不出来。）
**⇒ 主题只准改颜色；尺寸/排版出现在主题作用域里 = 密度被写进了配色。**

⚠️ **别把「空轨道」当缺陷。** `auto-fill` 的空轨道不画任何东西，它正是保证"项宽不随项数变"的机制；
`auto-fit` 消掉空轨道的代价是**项被拉伸**（实测 1220px 容器：3 项 399px、1 项 1220px）。
真正该量的是**塌缩**（计算出的轨道里出现 0px）。
⇒ 分界：**项数会变 + 项有自然尺寸 → `auto-fill`；项数固定 + 就该占满 → `auto-fit`。**
**一致性不是目的，一致地用错才是最贵的。**

## 10.1 判据本身也要验（这一节是四条判据翻车之后补的）

🔴 **一条判据必须能说出三种话，而且三种要长得不一样：**
```
通过     查过了，没问题
不通过   查过了，有缺陷
不适用   扫描域是空的 —— 什么都没查到
```
> **只有两态的判据，会把第三种情况报成"通过"。** 这就是"容错解析 + 空集合 = 免费的绿灯"换的一个形状：
> 上一次是解析容错吃掉了内容，这一次是**扫描域为空**。两次都在正常地亮绿灯。

**实例（本规格自己的 ④「无空轨道」）**，它同时错了三重：
```
① 测的不是缺陷 —— 空轨道正是那个机制本身（把机制当成了症状）
② 分不清两种模式 —— auto-fit 的计算值同样含 0px 轨道，两边都报 ⇒ 等于没有判据
③ 那次的绿是空集合的绿 —— 扫描域只有产品列表，而那一页是表格，一个格子都没有
```
**⇒ 判据里必须把"查过多少个"和结论一起报出来。** 看到 `0 个缺陷 / 查过 0 个`，才知道那个 0 不是结论。

🔴 **没见过它红的绿不作数。** 每条判据都要**当场**喂一个明知有问题的样本，确认它报得出来；
报不出来就当判据坏了、直接失败，不要用它的绿灯。
> 一次性的"我建它时验过"证明不了它今天还活着 —— 重构、正则改动、解析器换代都会让它悄悄失效。

⚠️ **判据的措辞要窄到能被证伪。** "无空轨道"听起来可测，实际上把机制、症状、和空集合混在了一起。
可证伪的写法是：**"同一个格子，项数从填满降到 1，单项宽度不变"** —— 它指名了会被看见的那件事。

## 11. 参考坐标

暗色 + 密集 + 专业工具这一路做得好的：**Linear · Vercel · Stripe 后台**。
共同点正是上面几条：极少的颜色、极强的明度层次、克制的字阶。

## 12. 令牌归属（防漂移）

品牌令牌（`--w3-*`）真源在官网 `skin/css/w3.css`，admin 只镜像不定义（已有 token-lint 闸守着）。
🔴 **本规格新增的密集模式令牌一律用 `--dz-*` 前缀**，定义在各后台自己的样式里。
⚠️ 两个后台必须用**同一份值**。**这份文件是那份值的唯一真源** —— 复制值到第二个地方之前，先想清楚谁是权威。
