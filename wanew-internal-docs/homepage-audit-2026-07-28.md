## 0. 结论

**四问都答了,但配比失衡:"卖什么"占了 8 块里的 3 块,而"凭什么信"排在它们后面。**

对一个 B2B 制造商来说,访客的顺序通常是**先判断你可不可信,再看你卖什么** ——
现在的首页是反过来的:先连看三块货,才轮到"我们凭什么"。

| 四问 | 由哪块承担 | 判定 |
|---|---|---|
| 我们是谁 | `w3-about` 块:About Us 眉题 + 完整段落 + 数字条 + Learn More→/about/ | ✅ **有(见 §3 更正)** |
| 卖什么 | Popular products + Shop by model + Field-proven = **3 块** | ✅ 但占比过重 |
| 凭什么信 | 数字条(4 项) + Our Advantages + 认证 | ✅ 有,但**位置靠后** |
| 该去哪 | 8 个按钮 + 底部 CTA 带 | ✅ |

## 2. 三条具体建议

### 2.1 hero 标题在描述品类,没有给主张
现在是 `Starlink Accessories One-stop Solution` —— 它说的是**这是个什么网站**,
不是**为什么该找我们**。眉题里那句 `Independent manufacturer · OEM/ODM` 反而信息量更大。
→ 建议:把"独立制造商 / 自产非贴牌 / 2010 年起"这类**身份主张**提到标题层,
品类词降到副题。⚠️ 这是文案改动,**要 Joe 拍**,我没动。

### 2.2 "凭什么信"应该更早出现一次
数字条已经在很前面,这是对的。但 **Our Advantages + 认证** 排在三块货之后。
→ 建议(小改):把**认证条**(FCC / CE / RoHS / ISO 9001)提到数字条旁边,
让"可信"在**第一屏之后立刻**完成,而不是等到第 6 块。Our Advantages 保持原位展开细节。

### 2.3 ~~"我们是谁"只有一行眉题~~ 🔴 **此条作废,见 §3**
**这条是错的。** 首页本来就有 `w3-about` 块(About Us 眉题 + 完整段落 + 数字条 +
`<a href="/about/">Learn More</a>`),**内容和链接都在,且在生产页正常渲染**。

## 3. 🔴 这份报告发出后被我自己推翻的一条(必须先读)

**§2.3「我们是谁只有 hero 一行眉题、About 内容一句没引用」是错的,已作废。**

真相:首页有完整的 `w3-about` 块 —— `About Us` 眉题 + 一整段身份文案(自产什么、服务哪些场景)
+ 4 项数字条 + `<a href="/about/">Learn More</a>`,**生产页实测全部正常渲染**。

**我是怎么错的**:我按 `<h2>` 划块来盘点首页,而 `w3-about` 用的是 **eyebrow + 段落,没有 h2** ——
**它整块从我的取样里消失了**。后来查"链接在不在"时又错了第二次:我取了 900 字符的窗口,
链接在窗口之外,于是得出"没有 /about/ 链接";直接 grep 才看到 `<a href="/about/">` 好好地在那儿。

⚠️ **后果是实的**:总工基于这条错误发现,**批准了"加一句我们是谁 + 链 /about/"这项工作** ——
如果我照做,就会在首页上**造出第二个重复的 About 块**。这正是我在下一节警告的东西,
而我自己就制造了一个。**已在动手前发现并叫停,没有实施。**

### 3.1 顺带:据此重估「认证条上提到数字条旁」这条建议
生产页真实顺序(按文档位置):hero → Popular products → Field-proven → **我们是谁+数字条** →
Our Advantages → **认证条** → Guides。
**数字条与认证条本来就已经彼此相邻**,而且**整个信任簇(身份+数字+优势+认证)都在第 4-6 位**。
所以"把认证条挪到数字条旁"**几乎不改变任何东西** —— 它并不能让"可信"在第一屏后立刻完成。
→ **真正的杠杆是把整个信任簇整体上移**(移到 Popular products 之前或紧随其后),
那是比已批准范围更大的结构改动,**需要总工/Joe 重新拍**。我没有擅自做。
