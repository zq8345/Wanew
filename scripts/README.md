# 写 `scripts/` 里的东西之前,先读这一页

这里记的**不是**代码规范,是**几个已经咬过我们、而且咬过不止一次**的坑。

每一条都配一个实例,而实例都是同一个形状:**这条坑早就被写下来了,写下来的人后来又犯了一次** ——
因为那份记录待在**被它描述的那个文件的头部**,而写新脚本的人不会去读旧脚本的头部。

> **一条只有"已经在现场的人"才会看到的警告,防不住"还没到现场的人"。**
> 所以它们搬到了这里 —— 你要写脚本,就正站在这个目录里。

概念层的判据失效模式在 `DESIGN.md §8`;这一页只管**动手时**的坑。

---

## ① `--json` 之类的机读输出,必须独占一条通道

**人读的输出和机读的输出共用一个 stdout,只要有一处漏判模式,机读那端就全废。**

```js
if (AS_JSON) console.log(JSON.stringify(payload));
else { …人读的… }
…
console.log("  ✅ 三项全过");        // ← 这一行没判 AS_JSON，JSON 后面多了一行散文
```

**做法**:每一处打印都判模式,或者干脆让人读的走 `stderr`、机读的独占 `stdout`。

**实例**:`zh-leak-scan.mjs` 的文件头里写着这个缺陷,标着"已知缺陷,押后修"。
**我读过那条,然后在 `routes-budget-check.mjs` 里造了一个一模一样的。**
修的时候还栽第二次:grep 到一处、改完、重跑 —— **还是失败,因为有第二处。**

> **"还有没有第二处"要靠枚举 `console.` 回答,不靠印象。**

## ② 在 bash 里写含反斜杠的正则,失败时**静默返回 0 个匹配**

转义层数取决于引号形式(`'…'` / `"…"` / heredoc / `node -e` 再套一层),**写错了不会报错,只会一个都匹配不到**。
而"0 个匹配"和"确实没有"长得一模一样。

**做法**:枚举一律用 ripgrep(或 Grep 工具),或者先把模式落进文件再读;**不在 bash 命令行里手写含 `\` 的正则**。
⚠️ 若必须在 bash 里跑,**先对一个你确知存在的样本试一次** —— 匹配不到就说明是转义坏了,不是没有。

**实例**:`verify-b.mjs` 的文件头写着这条(`$1/$2` 被 shell 吃掉、正则被分隔符咬断)。
**今天同一个坑,窗口和总工在同一天各栽一次** —— 两次都返回 0,两次都是靠"一个脚本都不按行切,不可能"这个直觉才回头查的。

> **靠"这个数不合理"发现问题是运气;靠对账发现问题才是制度。**

## ③ 检查器和被检对象一样需要被当成代码对待

**今天所有事故里,仪器出问题的次数多于被测对象出问题的次数。**

清点过的形态:正则漏简写属性 · 括号配平被字符串里的 `{{TOKEN}}` 带歪 · 截取跑过调用边界 ·
计量器嵌套读 0 · CRLF 让"已知相同"的对照物其实不同 · NFD 对中文是空操作让"已知不同"的其实相同。

**做法**:
- **每道闸都要有正对照** —— 用真实副作用制造一次它该红的状态,确认它真的红。
- ⚠️ **正对照失败时,先怀疑判据本身**:它证伪的可能不是被测对象。
  (实例:孤儿闸的分母写成"所有语种文件数合计 ≥ 68",移走整个 `en/products/` 后 es+pt 把总数补满,**闸没红**。
   漏掉的是某一个语种,而总数看不见它。)
- **setup 失败时,默认结果不能是"实验有效"** —— 先断言 setup 真的生效了,再看结论。
- **`cmd > file 2>&1; rc=$?` 三段式取退出码**;管道后的 `$?` 是管道最后一个命令的。

**实例**:`verify-b.mjs` 曾因为检查器自身的 bug,据此宣布"抽取器有跨 slug 状态串扰、之前所有数据作废"。
**那是假警报。**

## ④ 闸清单管到文件,管不到文件里少了几项

`data/gates.json` + `scripts/gates-check.mjs` 守的是**"哪些是闸、它们在不在"**。

**它守不到的**:一个闸文件还在,但**文件里少了几项断言**。

**实例**:cherry-pick 三条闸到新分支时,第 ⑨ 项(挂载桩与映射表的双向对账)留在了另一条未推的 commit 里,
同一个测试文件从 **106 条断言变成 51 条,而它照样打印"全部通过"**。
那次能发现,是因为数字掉了一半、大到刺眼 —— **如果掉的是 3 条呢?**

> 第一层:一条断言没验到 → 中止    「验不了 ≠ 验过了」
> 第二层:一整道闸不在   → gates-check 红   「闸不在 ≠ 闸通过了」
> **第三层:文件在、断言少了 → 目前没有东西守着。**

**动手时的做法**:改动/搬运闸文件之后,**记下改动前后的断言数**,数字下降必须有解释。

## ⑤ 报总数时,总数必须由清单算出来

**不许一边给出一份算出来的清单,一边另外手写一个总数。**

**实例**:同一条消息里既列了 24 条闸,又写着"实为 23 道" —— **两个数就摆在一起,没人对。**
(同一天另一个窗口也栽在这:"表格是算出来的、对的;错的是我在正文里手抄数字时挑错了列"。)
